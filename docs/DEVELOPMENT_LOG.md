2. PWA 初次連線安裝時快取站內文字、資料與本地素材，之後能離線開啟及全文查詢；外部原圖只能如實告知哪些真的已經在裝置快取。**不可將外部網址可讀、圖片成功回應或站內 SVG 數量當作全圖離線成功。**

5. 所有日文名稱／術法／地名**原文與臺灣繁中並存**，讓中文、日文都可搜尋。
6. 來源包括巴哈精華區及其外部連結；追查公開可檢索可讀取來源，逐項標已確認、待驗證、失效、403僅索引、歷史引用。**搜尋不到 ≠ 不存在**。
7. 正式更新要真實 git commit → GitHub Pages 部署 → Playwright 離線與手機尺寸驗收、正式 live 網站／圖片與資料一致性驗證。最後清楚報告版本／commit／站點／剩餘缺口。
8. 使用者不是工程師，現有工具能執行時直接完成，不要求操作命令列、不逐步索取同意。

### 實際踩過的問題與已採修正

- `index.html` 內嵌的 `guide-data` 與 `data.json` **必須完全一樣**，單改其中一個會令 CI 失敗。可用 `sync_site.py`，或讓編輯工具在單次任務內同時覆寫兩者。
- `tools/test_pwa.py` 曾錯用寫死舊資料版號，使 v0.9.6 的新內容被假判失敗；現版號與快取鍵需同步。測試用實際事件術語與真地圖，不能單看步數。
- 曾 11 個區域索引用完全同一張圖片，後已改為 10 個不同實際迷宮的來源圖作為「區域內地點例子」；珊瑚海缺圖則不能亂填。
- 曾 Service Worker 有 103 張本地 SVG，網頁的快取鍵卻不一致，致離線狀態顯示不準；已同步鍵。
- GitHub Actions 多次 push 連續部署可能互相 cancel；只看**最新 `main` commit 同一 SHA** 的 workflow／公開實際站點，不把被取消的上一輪當作失敗或成功。
- 若一個來源寫海賊五人、另一個寫六人，務必保留差異與相應來源；若霍克分支與一般路線報酬不同，亦需保留版本與分歧。
